# 写作规范：怎样把力学讲严谨

本库不是散文集，也不是公式手册。每一页都按同一套"可核对"的结构写，
目的是让学生**能自己把推导重做一遍**，而不是记住结论。

---

## 1. 六节固定结构

```
## 0. 结论先行
## 1. 前提与符号
## 2. 推导
## 3. 数值检验
## 4. 常见误解
## 5. 自测
```

### 0. 结论先行
- 用 1–3 句话说清"这一页要证明什么"。
- 给出**适用范围**（例如"仅适用于连续介质、小变形"）。
- 给出**与前后文的接口**（依赖哪一页、被哪一页使用）。

### 1. 前提与符号
- 假设逐条列出，每条注明"如果不满足会怎样"。
- 新符号必须在第一次出现处定义，并回到 `symbols-and-conventions.md` 对齐。

### 2. 推导
- **编号步骤**：每一步只做一件事（一次平衡、一次投影、一次代数变形）。
- 每一步写**依据**：静力平衡？几何投影？张量变换律？特征值定义？
- 禁止"显然""易得""可以证明"跳步。若某结论超出本页范围，明确写"这一步用到 X（见某页/某定理）"。
- 代数推导保留中间式，至少到"读者能接上"的程度。

### 3. 数值检验
- 用**能心算或计算器验算**的数字，不用复杂参数。
- 检验要能**证伪**：算出的数与另一条独立路径的结果对上，才算通过。
- 经典数字：单轴 100 MPa、纯剪 50 MPa、静水 100 MPa。这三个数在多个页面复用，便于交叉核对。

### 4. 常见误解
- 格式固定为：**错的说法 → 为什么错 → 正确的说法**。
- 误解必须是真实的（来自学生提问或常见教材误读），不写稻草人。

### 5. 自测
- 3–5 题，难度递增；至少一题要求动手算，至少一题要求判断对错并说明理由。
- 答案放在文末，先自己想。单页自测可用 `<details>` 折叠；**`<details>` 内只放行内公式**，
  独立公式（`$$...$$`）在折叠块里 GitHub 不解析，多组答案改用 `###` 分组。

## 2. 公式与图

- 行内公式用 `$...$`，独立公式用 `$$...$$`。
- 同一段落里最多留**一个**带下标的行内公式。两个带 `_` 的行内公式同段出现时，
  GitHub 会把两处下划线当成斜体标记配对，结果两处公式都不渲染
  （例： `$\mathbf{y}_0$` 与 `$J_{\mathbf{g}}$` 同段必坏）。改写办法：合并成一个公式，
  或把其中一个改成独立公式。
- 行内公式的开 `$` **左侧必须是 ASCII 空格**（行首或 ASCII 左括号 `(` 也可以）。
  紧贴任何非空格字符都不解析：中文标点（`，：、。；（）`）、中文引号（`“”`）、
  ASCII 引号与连字符（`"$x$"`、`-$x$`）都会让这一处公式原样显示成 `$x$`。
  实测只有"空格 + `$`"与"`(` + `$`"两种写法稳妥；中文引号内夹公式时写成 `“ $x$ 任意”`。
- 行内矩阵 `$\begin{bmatrix}...\end{bmatrix}$` 一律不解析（`pmatrix`、`smallmatrix` 同样），
  矩阵必须单独写成 `$$...$$` 块；行内只留"第 1 行 $(2,1)$， 第 2 行 $(0,3)$"这类文字描述。
- 收尾 `$` 右侧不受限制，紧贴 `，`、`。` 或右括号都能正常渲染。
- 符号首次出现时说明含义；不同页面同一符号含义必须一致。

### GitHub 数学渲染的硬限制

GitHub 会先按 CommonMark 规则把反斜杠当转义符处理一遍，再交给 MathJax。
凡"反斜杠 + ASCII 标点"的组合都会丢掉反斜杠，公式随之变形（实测，2026-11）：

| 源写法 | GitHub 上线后的结果 | 应写成 |
|---|---|---|
| `\,` `\;` `\:` | 变成 `,` `;` `:`，积分号、范数后多出标点 | `\ `（反斜杠 + 空格） |
| `\{` `\}` | 集合括号消失 | `\lbrace` `\rbrace` |
| 反斜杠 + 竖线 | 范数双竖线退化成单竖线 | `\Vert` |
| 行中的 `\\` | 矩阵换行失效，两行塌成一行 | 把 `\\` 挪到行尾 |
| `\\[6pt]` | 变成 `\[6pt]`，`\[` 被当成行间公式起点，整块坏掉 | 删掉 `[6pt]`，只留行尾 `\\` |
| `\%` | 变成 `%`，把百分号和同一行后半段注释掉 | 百分号写进正文 |
| 数学里的 `*`（如 `p_*`） | `*` 被强调语法吃掉，星区状态变成 `p_` | `p_{\ast}`（星号写成 `\ast`） |

配套经验：

- 行尾 `\\`（后面紧跟换行）不会被吃掉。`bmatrix`、`aligned`、`cases` 一律
  "一个物理行放一行"，不要把整个矩阵挤在一行里。
- 行尾也不要留 `\ `（反斜杠 + 空格）：GitHub 先裁掉行尾空格，剩下孤立的 `\`
  又会被当成换行，`\boxed{...}` 这类命令里就凭空断行。需要空隙就写在行中。
- 控制词后紧跟字母会粘成一个未定义命令（`\lbraceS_N` 直接报错），
  要写成 `\lbrace S_N`。
- `\operatorname`、`\phantom`、`\colorbox`、`\fcolorbox` 在 GitHub 黑名单里，
  报 "The following macros are not allowed"；用 `\mathrm{rank}`、`\mathrm{span}` 代替。
- `\_` 虽然会被吃掉一个反斜杠，但正好还原成下标，**不要随手改成 `_`**：
  一个行内公式里出现两处及以上下标时，Markdown 的强调语法可能把两个 `_` 当成斜体配对，
  整条公式都不渲染（实测 `$(\mathbf{A}\mathbf{b})_i = A_{ij}b_j$` 必坏，
  写成 `\_` 才稳；`$a_ib_i$` 这类词内下划线则安全）。独立公式 `$$...$$` 里正常写 `_`。
- `\boxed{...}` 不报错，但 Chrome / Edge 不画外框：MathJax 把它输出成
  `<menclose notation="box">`，而 Chromium 至今不支持这个 MathML 元素（Firefox 正常）。
  重点结论用加粗的 `**结论**` 一行标示，不要指望 `\boxed` 的方框。
- 百分号是唯一的例外：`\%` 被吃掉后 `%` 变成 TeX 注释符，
  线上会**丢掉百分号和同一公式行的后半段**。所以 `0.30%` 这类数字直接写成正文，
  不要塞进 `$...$`。
- 本地 MathJax 只查 TeX 语法，查不出上面这些转义与黑名单问题。
  推送后要把线上页面的 `data-latex` 与源文件逐条比对，确认没有"全部能渲染、但内容被改"的情况。
- 图必须**有编号 + 图题 + 一句话结论**（"从图中可以看到……"），不能只放图。
- 图必须由 `tools/make_figures.py` 生成，并在图题里给出文件名，保证可复现。
- 不复制他人图像；需要引用原图时放到 `assets/reference/` 并注明 DOI 与许可。

## 3. 语言

- 中文正文，专业术语中英并列一次（例："主应力（principal stress）"）。
- 句子短，一句话只讲一件事。公式前后各留一行说明"为什么写这个式子"。
- 不用"众所周知""不言而喻"；学生不懂的正是"众所知"。

---

## 4. 引用与出处

- 引用文献用 DOI 或完整链接，写在页面末尾的"延伸阅读"。
- 吸收外部文章（公众号、教材、论文）时，在 `cases/` 建独立笔记，
  正文只引用其结论，不搬运其文字与图片。
